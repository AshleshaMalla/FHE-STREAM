                           DESIGN PATTERNS

┌─ Separation of Concerns ──────────────────────────────────────────────────┐
│                                                                            │
│  Each module has ONE responsibility:                                      │
│                                                                            │
│  ✓ include/backends/*/  → Declare fixture class and interface            │
│  ✓ src/backends/*/Fixture.cpp → Manage lifecycle (setup/teardown)        │
│  ✓ src/backends/*/kernels_*.cpp → Implement benchmark algorithms         │
│  ✓ src/main.cpp → Bootstrap framework, MPI lifecycle                     │
│  ✓ CMakeLists.txt → Feature-flag-driven compilation                      │
│                                                                            │
└────────────────────────────────────────────────────────────────────────────┘

┌─ Adding a New Backend ────────────────────────────────────────────────────┐
│                                                                            │
│  1. Create: include/backends/<name>/<Name>Fixture.h                      │
│  2. Create: src/backends/<name>/<Name>Fixture.cpp                        │
│  3. Create: src/backends/<name>/kernels_<name>.cpp                       │
│  4. Add kernel: BENCHMARK_DEFINE_F + BENCHMARK_REGISTER_F                │
│  5. Update: CMakeLists.txt (add ENABLE_<NAME> option + sources)          │
│  6. No changes to: main.cpp, other backends                               │
│                                                                            │
└────────────────────────────────────────────────────────────────────────────┘

┌─ Adding a New Kernel to an Existing Backend ──────────────────────────────┐
│                                                                            │
│  1. Add BENCHMARK_DEFINE_F in the appropriate kernels_*.cpp              │
│  2. Add BENCHMARK_REGISTER_F(...)->Apply(RaiderSTREAM_Arguments)         │
│  3. No CMakeLists changes needed (file already compiled)                  │
│                                                                            │
└────────────────────────────────────────────────────────────────────────────┘

                     CRITICAL IMPLEMENTATION NOTES

┌─ Thread Management ───────────────────────────────────────────────────────┐
│                                                                            │
│  OpenFHE overrides OMP_NUM_THREADS internally. The DCRT fixture saves    │
│  and restores the thread count so benchmarks use all available cores:    │
│                                                                            │
│    const int saved = omp_get_max_threads();                              │
│    lbcrypto::OpenFHEParallelControls.SetNumThreads(1);                  │
│    omp_set_num_threads(saved);                                            │
│                                                                            │
└────────────────────────────────────────────────────────────────────────────┘

┌─ NUMA First-Touch ────────────────────────────────────────────────────────┐
│                                                                            │
│  #pragma omp parallel for schedule(static)                               │
│  for (size_t i = 0; i < nPolys; ++i) {                                 │
│    A[i] = ... // each thread first-touches its own NUMA-local pages     │
│  }                                                                       │
│                                                                            │
└────────────────────────────────────────────────────────────────────────────┘

┌─ Dead Code Elimination Prevention ────────────────────────────────────────┐
│                                                                            │
│  benchmark::DoNotOptimize(result);  // Keep result live                  │
│  benchmark::ClobberMemory();        // Memory fence between iterations   │
│                                                                            │
└────────────────────────────────────────────────────────────────────────────┘

┌─ Ciphertext Security Bypass ──────────────────────────────────────────────┐
│                                                                            │
│  CTFixture uses SetSecurityLevel(HEStd_NotSet) so that benchmarks can   │
│  run any RingDim/Depth combination without OpenFHE rejecting the        │
│  parameters. This is deliberate: we are benchmarking data movement,     │
│  not cryptographic security.                                             │
│                                                                            │
└────────────────────────────────────────────────────────────────────────────┘

┌─ MPI Iteration Deadlock Prevention ───────────────────────────────────────┐
│                                                                            │
│  CT_MPI_SENDRECV uses ->Iterations(10) to force both MPI ranks into    │
│  identical iteration counts. Google Benchmark's auto-calibration would  │
│  otherwise pick different counts per rank, deadlocking Send/Recv pairs. │
│                                                                            │
└────────────────────────────────────────────────────────────────────────────┘
